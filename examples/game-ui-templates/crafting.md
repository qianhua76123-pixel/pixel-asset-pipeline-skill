# 制作 UI：内容、画风、布局与交互拆解

本文展开本轮4款制作参考和软件现有3套制作美术提示词模板。制作UI围绕“做什么、消耗什么、得到什么、现在能否执行”组织；加工时间、NPC工钱和空间操作只有实际规则需要时才出现。

**证据约定**：截图可见内容与官方说明为来源证据，下面的模块、状态和动效是南方乡村项目的设计建议。未在本轮实机执行这4款游戏的制作流程。Pixel Studio当前生成静态美术并提供研究浏览，不会因选择模板自动获得配方、扣料、生产队列或工作台小游戏。

## 1. 先区分三种制作系统

| 系统类型 | 玩家真正做的决定 | 应同时看见 | 不应误加的机制 |
|---|---|---|---|
| 配方式制作 | 选配方、定数量、确认成本 | 产物、所需／已有材料、数量、结果 | 为每次简单制作强加研磨小游戏 |
| NPC加工服务 | 选师傅可做的产品、核对材料与工钱 | 服务者身份、产品、材料、费用、限制 | 把它写成无人物条件的随身制作 |
| 空间工作台 | 操作工具与材料，观察工艺结果 | 器具、材料、过程状态、产物反馈 | 只有一张漂亮工作台却没有对应操作规则 |

等待型生产可以附着在配方或NPC服务上，但不是所有制作都需要计时。只有规则确实存在才显示进度、队列、领取和取消；否则它们会制造错误承诺。

## 2. 玩家任务与信息优先级

| 玩家任务 | 优先内容 | 决策结果 | 失败时应保留 |
|---|---|---|---|
| 找到想做的物品 | 类别、配方身份、已解锁状态 | 选择准确配方 | 类别和浏览位置 |
| 判断能否制作 | 每种材料所需与拥有量、工作台条件 | 知道阻碍来自哪里 | 当前配方和缺料明细 |
| 选择制作数量 | 单次产出、批量成本、可制作上限 | 明确总产出与总消耗 | 合法范围内的输入数量 |
| 确认制作 | 产物、总成本、接收位置、必要耗时 | 发起一次有效操作 | 不凭空扣除材料 |
| 查看加工进度，若有 | 已接受的作业、状态、完成时刻或剩余时间 | 等待、取消或领取 | 可靠作业身份 |
| 继续做同一物品 | 更新后的库存和成本 | 无需重新找配方 | 选择、列表位置、上下文 |

材料和产物的关系比工艺装饰重要。让玩家离开配方页去背包反复查数量，会增加信息记忆负担；这是设计判断，不是本轮量化可用性测试的结果。

## 3. 逐区域模块、字段与视觉效果

以下字段是下游游戏实现建议，不是软件已提供的运行时接口。

| 区域 | 建议字段 | 内容与视觉效果 | 交互与依赖 |
|---|---|---|---|
| 工作台／服务身份 | `stationId`、`serviceNpcId` | 原创工具标记或小幅师傅肖像 | 限制可制作范围，人物不压过配方 |
| 分类 | `categoryId`、`categoryLabel` | 少量明确分类图标，当前项有形状标记 | 切换后保留各类浏览位置 |
| 配方清单 | `recipeId`、`name`、`icon` | 缩略图与可辨名称，选择态稳定 | 列表选择同步右侧详情 |
| 产物预览 | `outputItemId`、`outputPerBatch` | 独立清楚物品图，不画多件暗示额外产出 | 数量变化更新总产出 |
| 用途说明 | `description`、`effects` | 安静的真实中文区域 | 长说明可展开，不挤掉成本 |
| 材料行 | `ingredientId`、`required`、`owned` | 图标、名称、所需／已有量；不足带符号或文字原因 | 数量变化后重新计算每一行 |
| 材料来源 | `allowedContainers` | 只在有区别时说明背包／仓库取料范围 | 使用真实可访问容器，不把不可用物也计入 |
| 数量区 | `batchCount`、`maxCraftable` | 数字稳定，减、增、最大值语义明确 | 不允许负数、零次或过期上限提交 |
| 费用区，若有 | `feePerBatch`、`totalFee`、`balance` | 总价靠近确认操作 | 缺钱与缺料分别校验 |
| 计时／队列，若有 | `jobId`、`duration`、`status` | 已提交任务与配方浏览分层 | 只有服务接受后才表示进行中 |
| 确认区 | `canCraft`、`blockReason` | 可制作、不可制作和提交中明确区分 | 一次提交扣一次，防止重复触发 |
| 结果反馈 | `produced`、`consumed`、`destination` | 实际变化而非装饰性“成功” | 更新库存后继续核对材料 |

## 4. 四款实际界面比较

### Travellers Rest：设备分类与配方格

[官方来源](https://store.steampowered.com/app/1139980/) · 参考ID：`crafting-travellers-rest`

![Travellers Rest实际制作参考，非本项目素材](https://shared.akamai.steamstatic.com/store_item_assets/steam/apps/1139980/ss_d2730da225b405884172a1539dc12a988a4d8ab7.1920x1080.jpg?t=1793007805)

- **可见画风**：深棕木框与米黄内容面，物品图标色彩较丰富，边框和状态标记比背景清楚。
- **可见内容**：Oven标题、上部类别与肩键提示、中部菜谱格、所选Omurice摘要；摘要包括耗时、燃料和材料数量。
- **可见布局**：类别在上、配方格在中、摘要集中顶栏；缺料可见红底和0/2等数字，底部有搜索框，右下有条目说明。
- **设计分析**：当前配方与用料相邻，可减少在背包与制作之间来回查数；数量与形状状态应共同表达，不仅依赖红色。
- **交互推断**：静图支持“切分类／搜索→选配方→核对材料”的推论。批量、取消、队列和具体输入未实测。
- **迁移建议**：乡村烹饪或农具台可借分类与同屏用料关系，重做原创物品与木纸比例；不要照搬全部菜品、燃料和数值规则。

### STORY OF SEASONS: Grand Bazaar：配方、材料步骤与生产线

[官方手册](https://www.storyofseasons.com/grandbazaar/manuals/xbox/01/) · 参考ID：`crafting-grand-bazaar`

![Grand Bazaar实际制作参考，非本项目素材](https://www.storyofseasons.com/grandbazaar/manuals/xbox/img/ph/0149.png)

- **可见画风**：三维游戏上的二维暖色菜单，选中角标与色块状态清楚；不是像素绘制规格范本。
- **可见内容**：Select Recipe标题和Recipe→Materials步骤；左侧类别、配方格与滚动条，右侧Cheese图、材料、售价和加工时间。
- **可见布局**：左侧选择、右侧成品与用料主从关系明确；底部有材料表、生产线、退出和确认入口提示。
- **文档支持**：官方手册说明风车能加工不同物品，时间受类型和数量影响，并可查看同时运行的生产线。
- **未验证部分**：本轮未实际提交、取消或领取任务；不能仅由菜单确认扣料时机、失败处理和恢复行为。
- **迁移建议**：磨米、酿制等真实等待工艺可研究独立生产线；立即完成的竹编小物不需要为了画面完整硬加队列。

### Moonlighter：人物服务、材料与工钱

[官方来源](https://store.steampowered.com/app/606150/) · 参考ID：`crafting-moonlighter`

![Moonlighter实际NPC加工参考，非本项目素材](https://shared.akamai.steamstatic.com/store_item_assets/steam/apps/606150/ss_99f46056bb1d647adf3ea8f044bf016a8a3da428.1920x1080.jpg?t=1793636738)

- **可见画风**：米白纸面、青绿强调色与NPC同屏，沿用其背包页中的组件语言。
- **可见内容**：左侧服务NPC、中部Potion List、右侧所选产品大图与效果、拥有数量、费用和Recipe材料。
- **可见布局**：人物、产品、条件分三块；材料逐行列Req与Owned，满足有对勾，缺少有叉和零数量。
- **证据范围**：截图明确列费用、用料和按键提示，能证明这些可见条件；没有实测扣款、扣料、产出与背包满的处理。
- **迁移建议**：乡村木匠、裁缝和磨坊可参考“谁提供服务→做什么→材料和工钱”。资金不足、材料不足不能混成一条灰按钮。
- **边界**：这是NPC服务式制作，同图也用于商店比较；不应因此称为随身手作或纯金币买卖，更不能重复计作两张独立截图。

### Potion Craft：工具与材料本身成为操作对象

[官方来源](https://store.steampowered.com/app/1210320/) · 参考ID：`crafting-potion-craft`

![Potion Craft实际空间工作台参考，非本项目素材](https://shared.akamai.steamstatic.com/store_item_assets/steam/apps/1210320/ss_a5197ad5bb35e9899c9e751820cdb9dbc0ceb308.1920x1080.jpg?t=1793194728)

- **可见画风**：纸本炼金插画、器具和材料共同组成工作空间，不是像素菜单母版。
- **可见内容**：下方炼药器具、中央／左上带轨迹的炼金地图、右侧材料库存与左侧药剂信息。
- **可见布局**：大工具、地图与小库存图标按用途形成不同尺度，材料栏不是唯一的主操作区。
- **文档支持**：开发者商店说明可直接操作工具和材料炼药；具体研磨、搅拌、路线、试错节奏未在本轮实机操作。
- **迁移建议**：只有手艺过程本身是核心玩法时，才把灶台、砧板、原料与结果做成可操作对象。平铺工具布卷模板没有实现这种空间操作。
- **边界**：不能借一张图推断命中范围、连续动作、物理反馈、动画时序或误操作恢复；也不能把插画肌理直接视为精致像素规范。

## 5. 正常、边界与失败状态

下表为下游运行时设计建议；静态美术稿不会保证这些规则成立。

| 状态 | 内容与视觉效果建议 | 执行规则建议 | 恢复路径 |
|---|---|---|---|
| 正常可制作 | 配方、产物、材料、总数同屏 | 确认前再校验实际库存 | 成功后保持当前配方 |
| 未选配方 | 提示选择并保留列表 | 不显示上一配方的旧成本 | 选择一个配方 |
| 空分类／搜索无结果 | 空内容与筛选条件明确 | 不把无结果误报为未解锁 | 清筛选或切分类 |
| 当前选中 | 稳定边框或角标 | 焦点不等于开始制作 | 移动选择或确认 |
| 未解锁 | 可辨识的条目和允许公开的条件 | 不凭装饰锁图案创造规则 | 解锁后重新校验 |
| 缺材料 | 每行需要／拥有量与原因 | 缺料条目仍可检视 | 补齐后直接继续 |
| 缺资金，若有费用 | 工钱与余额分别可见 | 不和材料不足合并 | 资金变化后重算 |
| 数量超上限 | 当前合法范围可辨 | 库存变化时重算最大值 | 保留或修正到合法数量 |
| 背包／容器已满 | 接收目标与阻碍明确 | 确认前检查产物容量 | 整理后重试同配方 |
| 配方数据加载中 | 维持列表与等待状态 | 不把旧材料缓存当新配方 | 载入后恢复当前选择 |
| 提交中 | 一次清楚的处理中状态 | 防重复提交，保留操作身份 | 等待可靠结果 |
| 提交失败 | 原因与结果分离 | 不用“失败”假定材料一定未扣；先核对真实事务结果 | 以已知结果重试或恢复 |
| 进行中，若计时 | 只显示已接受作业的进度 | 离开和取消后果按真实规则 | 返回队列查看 |
| 已完成待领取，若有 | 完成与已领取不同 | 领取再次核对目标容量 | 容器可用后领取 |
| 成功 | 显示实际消耗与产出变化 | 更新所有受影响库存 | 允许继续制作 |

模板中“失败不消耗材料”是期望的游戏行为，不是现有静态美术代码提供的事务保证。真实实现需要原子校验与一致的失败恢复，不能用一张成功动图代替。

## 6. 一条完整的建议操作路径

```text
打开工作台／服务 → 选分类与配方 → 看产物和所需／已有材料
→ 设制作数量 → 核对总消耗、工钱与接收位置 → 确认一次
→ 得到明确结果 → 更新库存 → 保持配方继续制作或返回世界
```

如果存在等待生产，在“确认一次”后进入已受理作业，再由队列查看、完成与领取；如果存在空间手艺，选材与工具操作应单独设计，不假装是上述流程中的一张装饰图片。

| 操作 | 鼠标建议 | 键盘建议 | 手柄建议 |
|---|---|---|---|
| 分类与配方 | 点击选择，滚动不改变已选对象 | 方向移动列表，分类输入可发现 | 肩键切分类，方向键／摇杆选配方 |
| 看材料详情 | 点击或稳定悬停可检视 | 焦点进入材料行即可读全 | 可聚焦材料，不依赖鼠标悬停 |
| 改数量 | 增减与直接输入，滚轮不误改主页面 | 合法数字输入与明确提交 | 增减、最大值均可到达 |
| 确认制作 | 成本旁明确按钮 | 可重映射的确认操作 | 当前设备的统一确认按钮 |
| 返回 | 返回上一层并保留选择 | 返回优先关闭二级详情 | 返回不顺便取消已运行作业 |
| 查看队列，若有 | 单独入口 | 不与确认键共享一次输入 | 焦点返回原配方或原作业 |

## 7. 三套现有模板的准确区别

| 模板与准确ID | 默认画布 | 现有结构要求 | 选择依据 |
|---|---|---|---|
| 配方与材料 `game-ui-crafting-wood-paper` | 384×256，3:2 | 左配方清单；右上产物与说明；右中材料；右下数量、成本与确认 | 信息较多的日常配方页 |
| 工具布卷 `game-ui-crafting-cloth-grid` | 320×240，4:3 | 上沿配方带；中部3原料槽指向产物槽；下部说明、数量与确认 | 原料到产物关系较少的紧凑手作 |
| 手作札记 `game-ui-crafting-ink-ledger` | 384×256，3:2 | 左配方目录；右产物图与用途；下方材料账目行及确认 | 较安静的纸本工艺目录 |

三个原料槽是当前布卷美术方案的构图，不代表真实配方永远只能有3种材料，也不暗示自由试放合成。若项目配方超出该结构，应先调整布局合同，而不是省略材料。

当前通用要求是精致像素、正面平面、安静内容区和单一基础状态；中文、价格、材料数与状态标签留给运行时。选择模板后独立`uiPreset`保留结构规则；交互与状态建议不注入生图命令。

## 8. 南方乡村的材质、色彩与细节

| 设计维度 | 可迁移的原创方向 | 应避免的问题 |
|---|---|---|
| 器物身份 | 竹筛、木工尺、剪刀、陶罐、农具等与真实工艺对应 | 用任意中国符号代替功能 |
| 薄竹木纸面 | 稳定边角、米白静区、少量竹木纹 | 每个像素都加颗粒和高光 |
| 靛蓝工具布 | 布边与少量缝线，材料栏用浅衬片 | 写实密织纹覆盖数字区域 |
| 墨色札记 | 墨色块、留白、单一朱红重点 | 模糊晕染、书法乱码和半透明毛边 |
| 物品色彩 | 竹木、陶器、蔬果保留自然原色 | 为凑UI色板把所有物品染同一种绿 |
| 选中与缺料 | 轮廓、符号与实际数量配合 | 只靠红绿或全控件降透明度 |
| 场景关系 | 工作台与器物按实际用途联系 | 为“拟物”把普通配方画成强透视桌面 |

同一项目优先继承主题色、光源、图标身份和轮廓节奏。三套模板是可比较方向，不应在一个生产项目里让每张界面任意改用全新风格。

## 9. 中文、尺寸与像素生产边界

1. 配方名、材料名、数量分子／分母、费用和说明由游戏文本层绘制，不向生图模型请求可读中文。
2. 用最长中文配方、最多材料、零库存、大数量和多位数费用测试；不能仅用短英文判断区域足够。
3. 当前完整制作预设逻辑宽度至少256px、高度至少192px；默认是320×240或384×256。逻辑尺寸不是游戏最终窗口尺寸。
4. 图标、框角、分隔线与选中边使用可解释的共同像素尺度；整数倍最近邻放大后复查，不用平滑缩放掩盖毛边。
5. 图像外背景服从用户选择；控件内部纸面和布面可不透明。材料孔洞、细柄与小图标留白分别检查。
6. 图形图标不承担全部文本身份；肉眼分不清的近似材料需要真实名称辅助。
7. 数量区变更不能拉伸装饰角；如需九宫格组件，应另立组件规格，不把当前整屏美术稿当作已切片组件。

## 10. 动效与反馈建议

| 时刻 | 建议效果 | 保持条件 | 必须另外验证 |
|---|---|---|---|
| 切换配方 | 选择标记直接移动，详情稳定更新 | 不重排整张清单，名字与图标对应 | 快速切换不显示旧成本 |
| 调整数量 | 所需材料与总产出同步变化 | 数字位置稳定，可读性优先 | 长按、极值、库存变化 |
| 成功制作 | 一次轻微工具声或清楚结果标记 | 实际库存已更新才宣告完成 | 静音、无动画和重复输入 |
| 等待加工 | 与真实进度同步的小型状态 | 没有计时机制则不显示 | 离开、重进、重启后的状态 |
| 失败恢复 | 成本保留，原因靠近确认区 | 不用夸张闪屏替代原因 | 容器满、材料变化与服务失效 |

以上尚未由美术模板实现。无动画状态也应能辨认可制作、进行中和失败原因；不能把装饰性进度当作真实工艺进度。

## 11. 交付与验收

- 美术：产物、材料、文字静区、确认区和基本状态同屏检查，装饰不压过决策内容。
- 技术：尺寸、原生网格、alpha、边角连续性、图标留白与整数显示分别验证；提示词不是通过证明。
- 交互：在下游游戏中走完选择、改数量、确认、失败、继续制作、退出与恢复。
- 数据：材料与工钱只按真实结果变化；同时校验产物容器，防止重复提交和错误成功提示。
- 来源：商业截图只作远程研究，不能提取NPC、图标、字体或完整工作台当作项目资产。

目前交付是可选的静态美术规范和研究拆解；真实配方计算、扣料、计时队列、NPC条件与空间工具操作都需要独立实现，并以可运行结果验收。
