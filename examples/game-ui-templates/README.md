# 常用游戏UI：研究、效果与可用提示词

本资料包详细拆分**背包、商店、对白、制作**四类常用游戏UI；研究范围不包括网页、办公软件或非游戏产品。版本：2026-11-08。

覆盖10款游戏、14张独立实际截图、15项用途分析，以及软件现有12套精致像素静态美术模板。Moonlighter同一张NPC加工服务截图同时用于商店与制作比较，因此用途记录比独立截图多一项。

## 内容与效果怎样区分

1. **截图事实**：能够在指定游戏截图中直接看见的分区、材质、头像、图标、数值和按键提示。
2. **证据支持的交互**：截图或官方文字明确写出的功能范围，不扩大为完整实机验证。
3. **设计推断与建议**：我们对布局取舍、输入路径、恢复方式及动效的建议；不是商业游戏的已证实行为，也不是软件已经实现的玩法。
4. **生成约束**：希望模型遵守的像素、颜色、背景和区域规则；提示词不能保证成图质量。
5. **软件已实现效果**：模板选择、规范保存、提示词编译、参考浏览与普通四节点编排。完整UI仍是静态图片，游戏控件需要另外实现。

## 本轮交付边界

- 没有本轮新生成的12套成品UI，也没有以布局SVG冒充美术成品。
- 没有将背包、经济交易、分支对白或配方系统实现为可运行游戏。
- 商业截图仅引用官方远程来源，不包含在可再分发游戏素材包里，不自动发送给生图模型。
- 资料包是项目示例，位于仓库`examples/game-ui-templates`，不改变可独立安装的`skills/pixel-asset-pipeline`目录及其命令参数。
- 保留原色、细装饰、镂空和内部纸面是验收目标；自动处理结果仍需实际图像验证。

## 建议使用顺序

先选玩家任务和真实数据，再看同类截图比较；确定一套共同视觉方向后选模板，替换主体描述但保留结构化规范。先验证整屏主次、中文与状态，再生成和拆分生产组件。不要因为单张画面精致，就增加原本不存在的玩法、栏目或二级菜单。
