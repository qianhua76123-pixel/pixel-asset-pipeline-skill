# 四类游戏UI的视觉系统

[返回总览](README.md)。本章是面向南方乡村精致像素项目的设计建议，供模板取舍与成图验收使用，不代表已生成或已通过美术验收。

## 共同的视觉层级

| 层次 | 应承担的内容 | 预期效果 | 常见失败 |
|---|---|---|---|
| 游戏世界 | 场景、角色、正在交互的对象 | 让玩家知道界面从哪里打开 | 把整个世界变成完全不可辨识的黑底 |
| 任务界面 | 背包物品、货品、对白正文或配方 | 让主要决定比装饰更突出 | 木框、纸纹、人物立绘抢走主要面积 |
| 当前对象 | 选中物、说话者、待制作产物 | 清楚表达此刻针对谁行动 | 只改变颜色，无法看出焦点与选中差异 |
| 动作与代价 | 使用/购买/回答/制作及条件 | 行动与后果靠近，少依赖记忆 | 价格在一角，确认在另一角，原因只靠悬停 |
| 结果与异常 | 库存变化、获取物、缺料等 | 玩家知道发生了什么及怎样恢复 | 成功弹窗遮住新结果，失败后丢失原选择 |

上述为信息优先级，不是强制多层弹窗。布局能够说明关系时，不再补重复的次要标签。

## 三个可选美术方向

| 方向 | 材质表达 | 色彩角色 | 轮廓与纹理 | 适用气质 |
|---|---|---|---|---|
| 竹木纸面 | 薄竹木边、米白纸面、少量器物金属 | 暖竹木承担结构，纸面承担信息，灰橄榄绿承担选择 | 边缘稳定，木纹少，纸面安静 | 日常生活、农事与村镇服务 |
| 布面分区 | 靛蓝棉布、浅米衬片、竹编收纳 | 布面区分功能区域，浅面承载动态文字 | 缝线只在边缘，折边用明确色块 | 工具收纳、乡集、手工制作 |
| 墨色账本 | 米白纸、灰墨块、少量植物色及朱红 | 墨色组织结构，原物品保留自然色，朱红只作强调 | 留白与色块表达水墨，不用模糊晕染 | 货目、记录、安静叙事与手作 |

色名是候选角色，不是锁定的十六进制色板。已有项目主题色优先；没有确认色板时，不把“统一配色”写成已发生的自动锁色。

### 竹木纸面

- 正文的纸面应比外框更平静，主要物品图标的轮廓要比木纹更清楚。
- 竹木辨识来自边缘、厚度和少量节点，而不是在每个格子都画竹节。
- 店主肖像、商品、背包格和制作产物共享光源、材质抽象程度与视觉重量。
- 木框圆角/接头可以有主题特征，但不能把按钮和空面板都做成完全相同的卡片。

### 布面分区

- 分区应对应真实内容：工具、材料、食物或货品。不要为了画布面多加一个分类。
- 布边可以略软，内部物品格仍必须稳定，避免每格宽度与边距不同。
- 不把布料纹理当降噪目标随意抹平；先减少生成纹理，再检查清理是否破坏必要边线。
- 若正文区底色很深，文字需使用独立浅色语义并验证对比；当前模板倾向浅米衬片。

### 墨色账本

- 水墨像素由虚实、留白、墨色层级和边缘节奏体现，仍以清晰像素格组织。
- 不把物品、人物和所有图标全转成灰度。食材、陶器、衣物仍应保持项目颜色身份。
- 账本隐喻应参与信息组织：货目与明细、配方与材料，而非在纸页上照搬网页表单。
- 朱红强调不能同时表示选中、警告、消耗和关闭；形状、位置、文字共同区分状态。

## 按用途变化，保持同一套语言

| 用途 | 应增加的表现 | 应减少的表现 |
|---|---|---|
| 背包 | 物品身份、分类、当前动作、数量留白 | 大幅人物插画、重复的格子标签 |
| 商店 | 商人身份、商品差异、代价与交易结果 | 过高柜台、大面积场景装饰、无关货币图标 |
| 对白 | 说话者身份、表情、正文阅读空间 | 背景纸纹、复杂角饰、强烈常驻动画 |
| 制作 | 原料到产物的关系、可用性与成本 | 没有规则支持的装饰槽、虚假进度和队列 |

## 原生尺寸与屏幕尺寸

- 完整UI默认320×240或384×256；对白还提供320×160与384×192。这些是本项目模板起点，不是行业统一尺寸。
- 模型请求比例与逻辑画布一致，但API返回图片通常更大；必须通过像素处理建立真实逻辑网格。
- 48px人物标尺属于人物素材；不能据此把完整UI压成48px，也不能要求中文正文只占一个角色头部大小。
- 美术层按整数倍最近邻展示。运行时文字可以采用单独的清晰字体层，但需与像素美术的屏幕尺度协调。
- 不能因为文件尺寸是384×256就判定像素合格；还要检查alpha、滤波、边线节奏和内容读得清楚。

## 描边、色簇与原色

| 项目 | 建议规则 | 验收方式 |
|---|---|---|
| 外轮廓 | 同类框体与图标使用可解释的粗细，避免粗细随机跳动 | 在最终尺寸与最近邻局部放大下同时看 |
| 内部分隔 | 比主要轮廓轻，不把每个区域围成沉重黑框 | 灰阶检查主次，再回到原色 |
| 材质阴影 | 用稳定暗、中、亮色簇表达体积 | 看色簇是否成形，而非只数颜色 |
| 色阶 | 提示词中每材质3–5阶是表现目标，不是全图硬色数 | 检查材质区与整图色板分别变化 |
| 主题色 | 已给参考时保留颜色角色，避免橄榄绿偏成鲜青 | 与同源原图、同坐标对比 |
| 去污染 | 青紫污染必须与合法配色区分 | 检查原色、细装饰、孔洞和连续边线 |
| 抖动纹理 | 信息区尽量减少噪点；有意识的材质抖动应成组 | 区分有序纹理与随机单像素噪点 |

## 动态中文与数字

- 生成阶段保留空白文字区，不生成假汉字、占位横线、假价格和按钮文字。
- 程序层负责姓名、名称、描述、价格、库存、所需/拥有数量和状态原因。
- 先验证真实最长商品名、多行说明、大数值和长选项，再决定装饰框大小。
- 像素字体并不天然适合小字号中文；屏幕上读不清就扩大文字层或重排，不把整套UI继续缩小。
- 数字变化尽量不改变整行宽度；价格与数量同列对齐，必要时使用等宽数字。
- 独立文字层也要验证纹理背景、禁用态和选中态的对比。

## 透明与去底效果

| 区域 | 预期结果 | 要检查的错误 |
|---|---|---|
| 面板外侧 | 按所选规范透明或中性纯底 | 伪透明棋盘、彩色光晕、残边 |
| 内部纸面/布面 | 保持设计的不透明材质 | 抠图把浅纸或浅布当背景误删 |
| 真正孔洞 | 保留逻辑上需要的透明区域 | 清理自动填掉装饰镂空 |
| 细边与角饰 | 连续、粗细稳定 | 孤立点清理切断细线，补色填成粗杆 |

自动生成和去底没有通过全部12套真实成图测试。制作组件时应采用独立层和明确切片方案；当前完整UI模板不会自动输出这些层。

## 从整屏到组件的建议次序

1. 用真实世界场景确定界面的位置、面积和遮挡，不先堆满装饰。
2. 把同风格人物/物品、中文、控件与一个边界状态放到同一屏审查。
3. 通过单个任务的完整状态后，再扩展同类内容数量。
4. 明确哪些部分需要九宫格、重复边、独立图标、文字与点击区域。
5. 在游戏中实际打开、选择、确认/取消并恢复，然后再评价“好用”。

此顺序是制作建议，当前静态模板并未自动执行第4、5步。
