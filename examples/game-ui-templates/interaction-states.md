# 通用交互、状态与效果清单

[返回总览](README.md)。本章是游戏UI实现建议，不是本轮模板已经实现的游戏功能。每类专用状态见对应详细拆解。

## 四类UI中的一次完整任务

| 类型 | 进入原因 | 比较对象 | 主要动作 | 成功证据 | 恢复位置 |
|---|---|---|---|---|---|
| 背包 | 查找或处理拥有物 | 物品、用途、装备/存储目标 | 使用、装备、转移等真实支持动作 | 数量、装备、位置真实更新 | 当前物品/附近合理对象 |
| 商店 | 购买、卖出或委托服务 | 商品、数量、代价、持有资源 | 确认当前交易 | 货币与库存同时一致变化 | 当前货目与浏览位置 |
| 对白 | 与角色交谈或阅读叙事 | 说话者、当前句、可选回答 | 显示全文、继续、回答 | 进入下一句或产生明确剧情结果 | 正确说话者与叙事上下文 |
| 制作 | 制造或加工产物 | 配方、材料、拥有量、产量与费用 | 确认制作 | 材料减少、产物增加或队列状态改变 | 当前配方与制作条件 |

不能只设计成功瞬间。取消、失败、数据变化和重新打开都属于同一任务。

## 状态语义

| 状态 | 表达什么 | 建议视觉效果 | 建议行为 | 不应混同 |
|---|---|---|---|---|
| 正常 | 对象存在且可浏览 | 清楚图标、稳定底色 | 能选中与查看 | 当前选择 |
| 悬停 | 指针暂时经过 | 局部边框或轻亮变化 | 不产生交易/消耗 | 键盘焦点 |
| 焦点 | 下一次键盘/手柄输入的目标 | 可见且不只靠颜色 | 方向移动可预测 | 被选中并等待确认 |
| 选中 | 当前详情与动作针对的对象 | 单一稳定选择标记 | 详情、成本和动作同步 | 已装备/已购买 |
| 按下 | 动作正在触发 | 轻微内压或边线变化 | 避免重复触发 | 长时间进行中 |
| 不可用 | 有条件阻止当前动作 | 保留可辨对象与原因 | 仍可检查条件 | 空格、隐藏、锁定 |
| 空 | 没有对象或没有结果 | 保留结构与恢复入口 | 能返回/切分类 | 加载未完成 |
| 加载 | 数据尚未准备好 | 局部加载标记，不假装有结果 | 保持安全返回，不提交虚构数据 | 操作成功 |
| 进行中 | 已接受任务但尚未完成 | 与真实阶段对应的状态 | 按规则允许离开或取消 | 假进度条 |
| 成功 | 真实数据更新完成 | 原地数量变化、必要的获取反馈 | 可继续任务 | 仅按钮点击成功 |
| 失败 | 动作没有按预期完成 | 就近说明原因并保留输入 | 提供明确恢复路径 | 无声清空界面 |

图库的静态图片最多表达一个基础状态。完整状态集需要单独设计和程序绑定。

## 输入路径

### 鼠标

- 点击对象后，当前详情与可执行动作必须针对同一对象。
- 悬停可补充信息，但不是查看代价、原因或说明的唯一方式。
- 支持拖放时，需要明确拖起、目标有效/无效、落下结果和取消。未实现拖放时不要只因为参考图有格子就写进能力。
- 数量调整应显示最后确认值，按下和松开不能造成两次购买或制作。

### 键盘

- 进入界面时将焦点放在合理且可见的对象，不直接落在不可逆动作上。
- 常用选择、数量调整、确认、取消都有完整路径；不要把辅助动作仅放在右键菜单。
- 焦点与选中可以不同，但关系必须可理解；打开二级详情后，返回应恢复触发对象。
- 输入搜索/名称时不同时触发世界移动、快捷栏或关闭操作。

### 手柄

- 按可见布局建立邻接关系，跨分区移动时有可预测的目标。
- 局部滚动应跟随焦点；避免焦点移出屏幕而列表位置不变。
- 肩键切类的含义跨同类界面保持一致；没有分类时不保留虚假提示。
- 按键图形来自当前输入设备；不要把键盘字母烘焙进背景美术。

### 触摸（只有游戏支持时才适用）

- 触摸不能依赖悬停；先选后行动或明确的直接动作需保持一致。
- 控件的最终屏幕面积应便于点按，不能用原生像素尺寸直接当触摸目标。
- 长按、拖动与滚动冲突需要单独验证。本轮没有触摸实机测试。

## 动效与声音建议

下面是建议的反馈意图，不是商业参考游戏的已验证时序，也不是软件已实现动画。没有统一强制毫秒数，需按目标游戏节奏实测。

| 时刻 | 建议效果 | 功能目的 | 验证重点 |
|---|---|---|---|
| 打开 | 简短进入，正文迅速稳定 | 说明层级变化 | 不能在移动世界与UI间重复输入 |
| 选择 | 单一边框/色块转移 | 说明当前对象 | 不让装饰持续闪烁遮住图标 |
| 调数量 | 数字、总价、材料需求同步变化 | 让玩家看清代价 | 不先播放扣款再验证条件 |
| 成功 | 真实数量变化与轻量获取反馈 | 告知操作完成 | 不用遮挡式庆祝打断连续购物/制作 |
| 失败 | 就近说明阻止原因，必要时轻提示 | 指出恢复方法 | 不靠红色或声音单独表达 |
| 对白推进 | 文字显示与继续提示分开 | 保留阅读节奏 | 避免一键既显示全文又跳过下一句 |
| 关闭 | 回到世界并恢复合理焦点 | 完成任务 | 不重复触发NPC交互或掉落暂持物 |

提供减少动态时，应保留选中、结果和异常的静态证据；声音可增强反馈，但不能独立承载必要信息。

## 数据变化与一致性

- 所有购买、出售、使用和制作动作都需要在确认时核对当前条件，不能只依赖打开界面时的快照。
- 条件改变时更新可用性和原因，保留仍合理的数量与选择；夹紧数量时需让玩家看出变化。
- 不用“按钮变灰”代替库存与余额的真实更新。
- 失败后保留用户可恢复的输入；不要自动重试可能消耗资源的操作。
- 本地UI动作、远程请求和游戏存档的边界需要由游戏架构定义，本研究没有替代事务或存档实现。

## 真实中文测试数据建议

| 内容 | 需覆盖的边界 |
|---|---|
| 物品名 | 短名、长复合名、带品质/耐久的名称 |
| 数量 | 0、1、堆叠上限、超大仓库数量 |
| 价格 | 免费、余额刚好、差一点、最大显示值 |
| 说明 | 一行、多行、换行、未知属性 |
| 姓名 | 普通姓名、长称号、无姓名角色 |
| 对白 | 单行、多行、长句、无肖像、多个说话者 |
| 选项 | 1个、3个、长选项、不可选但需显示原因 |
| 制作条件 | 全材料齐、缺一种、多种缺失、产物容器满 |

这些是验收用例，不是已经写入游戏的数据，也不进入生图提示词。

## 验收顺序

1. 用真实内容验证玩家能完成任务；记录每一步的当前对象、条件与结果。
2. 验证键鼠与手柄的选择、确认、取消和恢复，不仅测试点击成功。
3. 在最终显示尺寸检查文字、状态与图标，再放大检查像素轮廓。
4. 检查数据更新后焦点、滚动、数量和说明是否一致。
5. 最后检查装饰、动效、声音和世界融合是否提升辨识，而不是遮挡内容。

技术通过、静态画面精致、可完成任务和玩家喜欢是四种证据，分别记录。
